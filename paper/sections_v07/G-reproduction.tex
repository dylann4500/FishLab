\section{Reproducibility and artifact availability}
\label{app:repro}

\subsection*{Availability}

The engine, every experiment artifact, the protocol, the generator that produces this paper's
numbers and the provenance checker that audits them are in the project repository,
\filepath{https://github.com/dylann4500/FishLab} (the repository's former name,
\texttt{dylann4500/fishbot}, redirects there). The original v1.0 build is the annotated tag
\texttt{sestina-v1.0}, which is not moved; the build described by this revised paper is the
annotated tag \texttt{sestina-v1.0-paper-r1}. Three identities are kept separate below: the frozen
policy configuration, which is the specification string and parameter vector of
Appendix~\ref{app:parameters} together with the mirror digest \texttt{\vsevenMirrorDigest{}}; the
evaluation binary, identified by its SHA-256; and the repository tree, identified by commits that
changed during the run. The evaluation of \S\ref{sec:results} ran at the commit whose current
short hash is \texttt{\vsevenBzeroCommit{}}; the full hashes of every commit named in this appendix
resolve in the repository. Two caveats attach to that hash and the subsections below give both:
the repository's history was rewritten after the evaluation, and no single commit describes the
tree for the whole run in any case.

\subsection*{Repository-history changes}

After the evaluation was complete, one artifact of the development phase, a per-decision search
capture of \vsevenKfiveBytes{} bytes, exceeded the hosting limit and was excised from version-control
history so the repository could be published. That rewrote every commit from phase 3 onward.

Three consequences, stated because a reader checking this paper against the repository will otherwise
be misled. First, the commit hashes recorded inside the phase-5 artifacts no longer resolve:
the verification block records \texttt{\vsevenBzeroCommitRecorded{}} and the freeze artifact's drift
check keys on \texttt{\vsevenFreezeCommitRecorded{}}, and neither object exists in the published
history. Every hash printed in this paper is the post-rewrite one, recovered by matching commit
subject lines, so the freeze commit is \texttt{\vsevenFreezeCommit{}} and the evaluation commit is
\texttt{\vsevenBzeroCommit{}}. Second, the seal predates the rewrite and is unaffected: the commit at
which the holdout material was sealed, \texttt{\vsevenSealCommit{}}, still resolves, so the
commitment chain of \S\ref{sec:evaluation-seal} is intact and independently checkable. Third, the
excised file is retained on disk and its digest recorded beside it in
\filepath{research/v07/results/K5-capture-7030004.sha256}, SHA-256
\texttt{\vsevenKfiveDigest{}\ldots}; it is regenerable from the capture harness and no measurement in
this paper depends on it.

\subsection*{Evaluation binary and source provenance}

Five commits landed in the repository while the battery was running, so no single commit describes
the tree for the whole of it, and a rewrite has since changed all of their hashes. Every one of the
\vsevenScoredCells{} scored cells was played by \filepath{engine/fish7}, SHA-256
\expandafter\hexdigest\expandafter{\vsevenBinarySha}, \vsevenBinaryBytes{} bytes, and that binary
was never rebuilt between the first bank digest and the last cell. The five later commits touch the
interactive browser table and not the policy; \S\ref{app:corrections-self} records the executed
check, rebuilding the engine from the tree as it stood at the end of the battery and recomputing the
mirror digest, that establishes the frozen policy is unmoved by them for the tested mirror, which is
evidence for the tested cases rather than a proof of global program equivalence.

\subsection*{Computing environment}

The scored battery ran on one Apple M5 Pro desktop with \vsevenMachineCores{} logical cores under
macOS (the record gives only the Darwin kernel version, \vsevenDarwinVersion{}), with every scored
cell at \vsevenScoredThreads{} worker threads
(Appendix~\ref{app:deviations}, D17) and the isolation audits at one; the throughput figure of
\S\ref{sec:game-why} was taken on the same machine at \vsevenMirrorThreads{} threads. The engine
was built with \texttt{clang++} at \texttt{-std=c++20 -O3 -march=native -funroll-loops
-fno-math-errno}, the evaluation build adding \texttt{-DFISH\_NO\_SERVE}. The compiler version and
whether the machine was otherwise loaded during the battery are not recorded, and the cost figures
of \S\ref{sec:results-cost} are wall-clock ratios taken under those conditions.

\subsection*{Experiment inventory}

The registered batteries and the cells measured for each are given in Table~\ref{tab:battery}
(\S\ref{sec:design-battery}); deviations D1 and D2 add a B5 reference cell and sixteen B9 cells,
because without them ``no single leave-one-out drop exceeds the whole'', ``the recovered size
tracks the planted size'' and ``the planted excess resolves to zero'' are not computable from the
cells the protocol lists. No cell was dropped.

\subsection*{Raw evaluation artifacts}

Under \filepath{research/v07/results/}, digested in
\filepath{research/v07/results/MANIFEST-P5.json}: \vsevenManifestRuns{} artifacts, of which
\vsevenManifestVerified{} re-verify against their recorded SHA-256 and byte count on disk at the time
this document was generated.

The block comprises \filepath{P5-B0.json}, the verification block (bank digests, the sealed
plaintext hash, the freeze round-trips, the seed registry, the engine self-audit and the
reproducibility runs); \filepath{P5-gate.jsonl}, the commit gate for all four configurations, rule
by rule; \filepath{P5-B2.jsonl} to \filepath{P5-B9.jsonl}, one JSON row per scored cell carrying
the literal argument vector it was produced by and the complete match object the harness emitted;
\filepath{P5-B10.jsonl}, one row per seat-isolation audit, carrying a \texttt{side} object with the
mismatch count and its denominator rather than a match object; the fitting traces
\filepath{P5-Z01.jsonl} to \filepath{P5-Z08.jsonl} and \filepath{P5-B9-h*.jsonl}, each with a
header, one record per generation and the final weight vector its adversary was rebuilt from; and
\filepath{P5-TABLES.txt}, the phase-5 reduction produced by \filepath{engine/p5_analyse.py}. Every
row carries its own argument vector, so any single cell can be re-run by hand from the artifact
without reference to this document or to the driver that produced it.

\subsection*{Numerical generation and provenance}

\begin{enumerate}
\item \filepath{engine/build_tables_v07.py}~\texttt{-{}-paper} reads the artifacts above and writes
  \filepath{paper/numbers_v07_generated.tex} and \filepath{paper/tables_v07/*.tex}. Every macro it
  emits carries a comment naming the artifact and field it came from, and re-emitting a name with a
  different value raises rather than silently winning.
\item \filepath{paper/check_provenance.py}~\texttt{-{}-version v07} audits the result: a number used in a section
  must either be generated from an artifact or sit under a comment header naming an artifact that
  exists on disk. Of the numbers the sections use, \vsevenProvGenerated{} are emitted by this
  cycle's generator, all but the registered training figures of Table~\ref{tab:selection} computed
  from the phase-5 artifacts and those four carried in the generator as constants of the protocol;
  \vsevenProvInherited{} are generated from earlier cycles' artifacts by those cycles' generators;
  and \vsevenProvTranscribed{} are transcribed under a header naming a source document.
\item \filepath{paper/inline.py} flattens the modular source into a single self-contained file.
\end{enumerate}

Sections~\ref{sec:game}--\ref{sec:background} quote results from this programme's earlier cycles;
those numbers are loaded from the earlier cycles' own generated files rather than retyped, and the
provenance checker verifies that every transcribed number's named source exists on disk.

The generated file is \verb|\input| after the placeholder file, so a value in the placeholder can never
reach a PDF built after the battery has been run. Generated on \vsevenBuildDate{}.

\subsection*{Sample sizes}

The project's sample-size planning rule is a $95\%$ half-width of $98/\sqrt{N}$~pp at parity for
$N$ independent games, computed by the harness and emitted with every cell
(\S\ref{sec:evaluation-power}); it is a planning approximation, not a power calculation. At
\vsevenBtwoFcheapN{} games the primary claim's pooled half-width is
\vsevenBtwoFcheapHalfWidth{}~pp; the frontier cells are sized so that the primary claim's
half-width is small against the \vsevenPrimaryFloor{}-point reference bar rather than against the
effect. Far-class panel members are
sized at a quarter of the near class deliberately: they are decided by \vsevenFarSpanLo{} to \vsevenFarSpanHi{}~pp
and do not need the resolution.
